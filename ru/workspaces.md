# Одна база для нескольких проектов

Рабочая база — отдельный каталог, который можно хранить в закрытом Git-репозитории. В нём находятся исходники навыков, определения MCP и заметки проектов. Файл `workspace.json` выбирает для каждого проекта нужные элементы. Путь к checkout задаётся при запуске на своей машине.

## Испытать на двух проектах

**Совместимость клиентов на Windows.** В Codex CLI 0.166.0 и Claude Code 2.1.316 проверены навыки, проектные инструкции и выборочное подключение MCP. В отдельном испытании Codex CLI 0.41.0 прочитал инструкции в обоих проектах, но пропустил общий навык и выбранный для проекта документации MCP. При таких симптомах проверьте версию командой `codex --version`. Совместимость промежуточных версий Codex здесь не проверялась.

Потребуются Git и Python 3.11 или новее. Запустите из корня Project Fieldnotes. Для испытания выберите два новых каталога. В системах, где Python 3 называется `python3`, замените имя команды.

```sh
git init ../lantern-trial
git init ../docs-trial
python fieldnotes.py plan examples/workspace lantern ../lantern-trial
python fieldnotes.py apply examples/workspace lantern ../lantern-trial
python fieldnotes.py plan examples/workspace docs-site ../docs-trial
python fieldnotes.py apply examples/workspace docs-site ../docs-trial
```

Откройте каждый checkout в Claude Code или Codex. Для доверенного проекта используйте штатный диалог доверия и подтверждения MCP. В новых сессиях обоим проектам доступен навык `decision-review`. У `lantern` есть заметки о регистрации билетов. У `docs-site` — заметки о документации и подключение `protocol-docs`. В списках клиентов также могут быть ваши личные серверы.

Измените [канонический навык](../examples/workspace/skills/decision-review/SKILL.md), выполните `plan` и `apply` отдельно для обоих проектов. Изменение появится в обоих клиентах. Следующий `plan` должен показать ноль файлов к изменению.

## Подключить свою базу

Скопируйте [образец базы](../examples/workspace/) в отдельный закрытый каталог вне целевого checkout. В `workspace.json` для каждого профиля укажите каталог заметок с `START-HERE.md`, список имён навыков и список MCP. Заметки и навыки копируются целыми каталогами со вспомогательными файлами. Помещайте туда только материал для получателя. Секреты и учётные данные храните локально.

Для удалённого MCP задайте `url` с HTTPS. Для локального — `command` и список `args`. Исполняемая команда должна быть доступна на машине. Синхронизация записывает конфигурацию. Подключение запускает сам клиент.

## Где виден результат

- Заметки появляются в `.fieldnotes/notes/`, навыки — в каталогах клиентов `.agents/skills/` и `.claude/skills/`. Новые копии заметок и навыков исключаются из обычного добавления в Git.
- В `AGENTS.md` и `CLAUDE.md` добавляется помеченная секция со ссылкой на стартовую страницу. Для MCP управляются секция `.codex/config.toml` и отдельные записи `.mcp.json`. Остальные ключи сохраняются. Проверьте diff клиентских конфигураций перед коммитом.
- Конфликты с ручными правками видны уже в `plan`. Согласуйте правку с исходником и восстановите управляемую копию перед повторным применением. Прерванный `apply` можно повторить. Если удалить навык или MCP из выбора проекта, следующий `apply` снимет его управляемую копию. Журнал хешей хранится в локальных метаданных Git.
